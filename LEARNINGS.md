# Learnings: Multiplayer and Collaboration Deep Linking

- **Deep Linking in Angular:** Using `ActivatedRoute.queryParamMap.subscribe` in `ngOnInit` is essential for handling parameters that might arrive after the component has initialized or when navigating between routes that use the same component.
- **Clipboard API:** `navigator.clipboard.writeText` provides a standard way to copy URLs to the clipboard, but it requires a secure context (HTTPS or localhost) and user interaction.
- **Backend Error Handling:** Always check for missing function definitions in Node.js when adding new features, as it can lead to runtime crashes even if the syntax is valid.
- **Angular Signal Sync:** When using signals (like `selectedGame`), updating them based on query params ensures that the UI reactively opens the correct views (like the game preview overlay).
- **Authentication Resilience:** Verification that `authGuard` preserves query parameters (`returnUrl`) ensures that deep links work even for unauthenticated users after they log in.

# Learnings: Studio Vocal Capture & Audio Enhancement

- **Monitor vs. capture graphs:** A `MediaRecorder` bound to the raw `getUserMedia` stream silently bypasses every Web Audio insert (mic gain, pitch correction, vocal mastering). Tap the finished chain with a `MediaStreamAudioDestinationNode` instead, so takes capture exactly what the artist hears; fall back to the raw stream when no chain is attached.
- **Guard repeated fan-out taps:** `AudioNode.connect()` sums, so re-attaching the same chain node doubles the signal. Track the currently tapped node (and its AudioContext) and disconnect the previous feed before connecting a new one.
- **Hot-plugged interfaces:** Register a `devicechange` listener and preserve `selectedDeviceId` while it is still present, so unplugging a USB mic falls back cleanly instead of leaving a dead selection. Avoid prompting for permission on service construction; request labels only when the user actually primes the interface.
- **Never swap inputs mid-take:** Re-initializing a `MediaStream` while `MediaRecorder` runs truncates the take, so refuse the switch and expose `canSwitchDevice` to the UI.
- **Non-destructive enhancement:** Render MP3/WAV upgrades through an `OfflineAudioContext` (rumble filter → tone shaping → glue compression → true-peak normalize) into a separate `enhancedBuffer`, and keep the decoded original so "Restore Original" is always available.
- **Keep toggles truthful:** A noise-gate switch that only stores a flag is a lie; wire it into the live graph (gate `GainNode` between mic and capture destination, fast attack / slow release) and reorder the graph build so the very first take is already gated.

# Learnings: Studio Mobile (Android Chrome) Layout & Touch

- **`touch-action` is inherited by intersection, not by cascade:** A wrapper declaring `touch-action: pan-y` disables horizontal panning for *every* descendant, and no child can opt back in — a child's `touch-action: pan-x` only ever narrows the set. The Studio shell's mobile `.comp-view { touch-action: pan-y }` therefore made the piano-roll grid, score ruler, mixer rail, drum step rows and sound-browser chips unreachable on phones even though each declares its own `pan-x pan-y`. Only set a restricted axis where nothing inside needs the other one, and let drag surfaces (`touch-action: none`) opt out individually.
- **Group opacity hides fixed children:** `opacity: 0` on an ancestor composites the whole subtree as one group, so a `position: fixed` restore button inside a collapsed footer stays invisible no matter what `opacity` it sets itself (while remaining clickable — a ghost button). Use `visibility: hidden` on the ancestor plus `visibility: visible` on the button: visibility is inheritable *and* overridable, opacity is not.
- **Restore affordances must outrank responsive utilities:** The header-collapse button carries `hidden md:grid`, so collapsing the topbar on a wide viewport and then rotating/narrowing below 768px removed the only way back to the transport bar. When a control toggles a *hidden* state, make its re-show rule the most specific one in the file.
- **Landscape phones are the tightest workspace:** ~44px topbar + ~48px tool row + ~52px dock leave a phone's ~360px height with ~215px of canvas. `isCompactMobile` keys off width alone, so landscape (769-932px) still gets the desktop-ish shell — trim chrome by *viewport height* (`orientation: landscape and (max-height: 480px)`), and cap any fixed-height lane (quick-start card) so it can never push the canvas out of the `100dvh` shell.
- **Resolve canvas hit tests in CSS pixels:** The shared waveform renderer keeps a fixed 800px backing store stretched by CSS, so a hit radius expressed in internal pixels silently shrinks with the display scale and pixel-precision handles become ungrabbable on a phone. Compare against `getBoundingClientRect().width` and widen the slop for `pointerType === 'touch'`.
- **Pointer Events for drag handles:** `mousedown`/`mousemove` drags (loop handles, etc.) never fire for a finger. Register `pointerdown`/`pointermove`/`pointerup` with `setPointerCapture`, feature-detect `'PointerEvent' in window` so jsdom keeps exercising the mouse fallback, and pair it with `touch-action: none` on the interactive surface only.

# Learnings: Sequencer Surfaces (Arrangement · Channel Rack · Piano Roll)

- **A clip must resolve to a pattern, not to "the track's notes":** once a track holds more than one pattern, `activePatternSlotId` is only the *editing* cursor. Playback must read `clip.patternSlotId` and fall back to the live pattern; a clip whose referenced slot is empty should stay silent instead of leaking whatever is currently being edited.
- **Snapshot the pattern you leave:** creating a new pattern by swapping the live notes strands every clip still pointing at the old slot on that slot's stale first version. Append the pre-switch notes as a new version of the *previous* slot inside the same command so undo restores both the slot list and the notes.
- **Pattern time is clip-local:** gating playback on the global bar phase makes a clip dropped at bar 6 wait up to four bars for its step 0. Compute the step from the clip's own start (`step - clip.start * stepsPerBar`) and modulo the pattern length.
- **Note hit tests are half-open:** `[start, start + length)` — testing `<=` on both ends makes adjacent notes overlap by one grid cell, so clicking the seam between two notes grabs the wrong one and selections come back one note too wide.
- **Prefer computed projections over template math:** the template can call signals but cannot import `Math`; expose a `marqueeStyle()` computed returning a ready-to-bind style object rather than open-coding `Math.min` in the template.
