# Learnings: Multiplayer and Collaboration Deep Linking

- **Deep Linking in Angular:** Using `ActivatedRoute.queryParamMap.subscribe` in `ngOnInit` is essential for handling parameters that might arrive after the component has initialized or when navigating between routes that use the same component.
- **Clipboard API:** `navigator.clipboard.writeText` provides a standard way to copy URLs to the clipboard, but it requires a secure context (HTTPS or localhost) and user interaction.
- **Backend Error Handling:** Always check for missing function definitions in Node.js when adding new features, as it can lead to runtime crashes even if the syntax is valid.
- **Angular Signal Sync:** When using signals (like `selectedGame`), updating them based on query params ensures that the UI reactively opens the correct views (like the game preview overlay).
- **Authentication Resilience:** Verification that `authGuard` preserves query parameters (`returnUrl`) ensures that deep links work even for unauthenticated users after they log in.

# Learnings: Studio Vocal Capture & Audio Enhancement

- **Monitor vs. capture graphs:** A `MediaRecorder` bound to the raw `getUserMedia` stream silently bypasses every Web Audio insert (mic gain, pitch correction, vocal mastering). Tap the finished chain with a `MediaStreamAudioDestinationNode` instead, so takes capture exactly what the artist hears; fall back to the raw stream when no chain is attached.
- **Guard repeated fan-out taps:** `AudioNode.connect()` sums, so re-attaching the same chain node doubles the signal. Track the currently tapped node (and its AudioContext) and disconnect the previous feed before connecting a new one.
- **Hot-plugged interfaces:** Register a `devicechange` listener and preserve `selectedDeviceId` while it is still present, so unplugging a USB mic falls back cleanly instead of leaving a dead selection. Avoid prompting for permission on service construction; request labels only when the user actually primes the interface.
- **Never swap inputs mid-take:** Re-initializing a `MediaStream` while `MediaRecorder` runs truncates the take, so refuse the switch and expose `canSwitchDevice` to the UI.
- **Non-destructive enhancement:** Render MP3/WAV upgrades through an `OfflineAudioContext` (rumble filter → tone shaping → glue compression → true-peak normalize) into a separate `enhancedBuffer`, and keep the decoded original so "Restore Original" is always available.
- **Keep toggles truthful:** A noise-gate switch that only stores a flag is a lie; wire it into the live graph (gate `GainNode` between mic and capture destination, fast attack / slow release) and reorder the graph build so the very first take is already gated.

# Learnings: Studio Mobile (Android Chrome) Layout & Touch

- **`touch-action` is inherited by intersection, not by cascade:** A wrapper declaring `touch-action: pan-y` disables horizontal panning for *every* descendant, and no child can opt back in — a child's `touch-action: pan-x` only ever narrows the set. The Studio shell's mobile `.comp-view { touch-action: pan-y }` therefore made the piano-roll grid, score ruler, mixer rail, drum step rows and sound-browser chips unreachable on phones even though each declares its own `pan-x pan-y`. Only set a restricted axis where nothing inside needs the other one, and let drag surfaces (`touch-action: none`) opt out individually.
- **Group opacity hides fixed children:** `opacity: 0` on an ancestor composites the whole subtree as one group, so a `position: fixed` restore button inside a collapsed footer stays invisible no matter what `opacity` it sets itself (while remaining clickable — a ghost button). Use `visibility: hidden` on the ancestor plus `visibility: visible` on the button: visibility is inheritable *and* overridable, opacity is not.
- **Restore affordances must outrank responsive utilities:** The header-collapse button carries `hidden md:grid`, so collapsing the topbar on a wide viewport and then rotating/narrowing below 768px removed the only way back to the transport bar. When a control toggles a *hidden* state, make its re-show rule the most specific one in the file.
- **Landscape phones are the tightest workspace:** ~44px topbar + ~48px tool row + ~52px dock leave a phone's ~360px height with ~215px of canvas. `isCompactMobile` keys off width alone, so landscape (769-932px) still gets the desktop-ish shell — trim chrome by *viewport height* (`orientation: landscape and (max-height: 480px)`), and cap any fixed-height lane (quick-start card) so it can never push the canvas out of the `100dvh` shell.
- **Resolve canvas hit tests in CSS pixels:** The shared waveform renderer keeps a fixed 800px backing store stretched by CSS, so a hit radius expressed in internal pixels silently shrinks with the display scale and pixel-precision handles become ungrabbable on a phone. Compare against `getBoundingClientRect().width` and widen the slop for `pointerType === 'touch'`.
- **Pointer Events for drag handles:** `mousedown`/`mousemove` drags (loop handles, etc.) never fire for a finger. Register `pointerdown`/`pointermove`/`pointerup` with `setPointerCapture`, feature-detect `'PointerEvent' in window` so jsdom keeps exercising the mouse fallback, and pair it with `touch-action: none` on the interactive surface only.

# Learnings: Sequencer Surfaces (Arrangement · Channel Rack · Piano Roll)

- **A clip must resolve to a pattern, not to "the track's notes":** once a track holds more than one pattern, `activePatternSlotId` is only the *editing* cursor. Playback must read `clip.patternSlotId` and fall back to the live pattern; a clip whose referenced slot is empty should stay silent instead of leaking whatever is currently being edited.
- **Snapshot the pattern you leave:** creating a new pattern by swapping the live notes strands every clip still pointing at the old slot on that slot's stale first version. Append the pre-switch notes as a new version of the *previous* slot inside the same command so undo restores both the slot list and the notes.
- **Pattern time is clip-local:** gating playback on the global bar phase makes a clip dropped at bar 6 wait up to four bars for its step 0. Compute the step from the clip's own start (`step - clip.start * stepsPerBar`) and modulo the pattern length.
- **Note hit tests are half-open:** `[start, start + length)` — testing `<=` on both ends makes adjacent notes overlap by one grid cell, so clicking the seam between two notes grabs the wrong one and selections come back one note too wide.
- **Prefer computed projections over template math:** the template can call signals but cannot import `Math`; expose a `marqueeStyle()` computed returning a ready-to-bind style object rather than open-coding `Math.min` in the template.

# Learnings: Studio Module-Wide UI Audit

- **A segmented control with hard-coded `active` is dead UI:** the Mixer's `Strips / Sends / Routing` group rendered one pill as permanently active and gave the other two no `(click)` handler, so the send and routing surfaces were unreachable. Drive every segment from one signal and bind `[class.active]` plus `[attr.aria-pressed]` to it — a decorative toggle survives visual review but fails a behavioural one.
- **Hard-coded knob `[value]` bindings read as working controls:** the Effects Rack rendered `[value]="60"` grids with no `(valueChange)` handler, so the whole parameter panel was a picture. Bind each knob to the slot's stored parameter and write moves back through the manager, with the spec default used only when the slot has never stored that key.
- **`<button>` cannot contain `<button>`:** the HTML parser hoists nested buttons out of their parent, orphaning the inner actions (mixer/channel rows, performer take cards, session clip slots, rack slots). Use a `div` with `role="button"` + `tabindex="0"` + `(keydown.enter)` for the container and keep real buttons inside it.
- **Pointer-initiated drags need release and cancel, not just move:** the shared knob bound `mousedown` and a global `mousemove`, but never listened for `pointercancel`/`lostpointercapture`, so an Android Chrome gesture takeover left the knob "stuck" to the finger. Attach with `setPointerCapture`, keep the window listeners only for the mouse fallback, and clear any pending double-tap timer in `ngOnDestroy`.
- **Audit comments are not markup:** a template scan for dead buttons must strip `<!-- ... -->` first, or the explanatory comments added by an earlier cleanup pass (`used to be a <button class="active">`) report as live defects.
- **A send return with no processor is not a send:** `sendAReturn`/`sendBReturn` went straight into `masterGain`, so raising SND A/B merely re-added the dry track at the send gain — a second gain stage, not an effect. A return must terminate on a processor (Send A → master convolver, Send B → tempo-synced echo). Tap sends from the per-track fader, never from `masterGain`, or the return feeds its own send.
- **An empty service method is an invisible dead control:** `InstrumentService.setReverbMix(_val) {}` left the Master Controls REVERB fader fully interactive with no audible effect, and the engine's `reverbWet` gain had no input at all because the convolver was built and never connected or given a buffer. Scan for empty method bodies whose names appear in templates or are called from components — a no-op setter is as dead as a missing handler.
- **Generate impulse responses from a seed, not `Math.random`:** a random IR differs between the live graph and the `OfflineAudioContext` bounce, so the exported file does not match what the artist heard. A seeded xorshift32 makes both renders share one room.
# Learnings: Studio DSP Read-Back Integrity

- **An effect class must expose what it was set to:** the built-in rack plugins fed the WASM worklet and the project snapshot from `getParam`, and three of them returned hard-coded constants (`Reverb` mix always `0.5`, `Distortion` amount always `0.5`, the sidechain always its defaults), so the worklet was configured with values the artist never chose. Track the value on the DSP class (`get mix()`, `get amount()`, `get threshold()`) and read it back.
- **`setTargetAtTime` params cannot be read back:** `Delay` and `Equalizer` ramped their AudioParams, so `param.value` returns the *previous* level — and in an `OfflineAudioContext` bounce it never settles at all. Keep the dialled value in a tracked field and report that; `getBands()` reading `filter.gain.value` also made the worklet EQ sync lag one move behind.
- **Setting one parameter must not rewind the other:** `SidechainPlugin.setParam` routed the untouched parameter back to its literal default (`configure(id === 'threshold' ? value : -30, ...)`), so nudging Ratio silently reset Threshold. Touch only the parameter that moved.
- **`params: []` on a plugin that advertises bands is a lie:** the 7-Band EQ exposed an empty `PluginParam[]`, hiding seven bands from anything that enumerates `params` (automation, the plugin store, a params-driven UI). Build the descriptor list from the actual filters, and keep each descriptor's `value` in sync on `setParam`/`reset`.
- **An interface method with an empty body is a contract violation:** `IAudioPlugin.reset()` documents 'reset all parameters to defaults' while all six built-ins implemented `reset(): void {}`. Implement it against the tracked DSP and `defaultValue`s so a host that calls it gets the documented behaviour.

- **Zero the pinch reference span on touchend:** `handlePinch` only clears `lastPinchDistance` when handed a frame with fewer than two touches, and lifting both fingers never produces one — the next pinch is measured against the previous span and jumps on its first frame. Grid handlers must call an explicit reset from their `touchend`.

# Learnings: Studio AI Session Musicians

- **One owner per transport hook, everyone else observes:** `engine.onScheduleStep` is assigned (not subscribed), so a second claimant silently wins and kills the first. The AI band registers through `MusicManagerService.onStep()` instead — an observer set that is notified *after* the arrangement renders, so a generated note can neither mute, delay nor displace what the artist wrote.
- **Report what sounded, not what was enabled:** `renderStep` used to push a musician into its `played` list on the subdivision gate alone, so the strip advertised `LIVE` on steps where the part had bailed out (muted kit, no anchor track, dead AudioContext). Have each `play*` helper return whether it triggered, and build the read-out from that.
- **A velocity ternary on the gate you already passed is dead code:** the AI drummer only fired on `step % 4 === 0`, then picked `step % 4 === 0 ? 0.95 : 0.6` — always `0.95`, so the backbeat snare hit as hard as the kick. Test the *accent* condition (`isBackbeat`) instead of re-testing the gate.
- **Don't re-derive the anchor per player:** the bassist re-searched the arrangement for a note onset on the exact step it played, so it dropped out on every step without a human note while the keyboardist anchored to whatever `findRoot` happened to return from another track. Resolve one `{ track, root }` anchor per step and build every generated part from it.
- **`Math.random()` gates make a jam unreproducible and untestable:** the keyboardist rolled `Math.random() > 0.7` per step, so a good take never landed the same way twice and no spec could assert it. A fixed off-beat subdivision (steps 2, 6, 10 …) reads as intentional playing and is verifiable.
- **Clear live read-outs on detach, before the early return:** `detachNow()` started with `if (!this.detach) return`, so a roster that never subscribed still advertised the last bar it played. Reset the read-out first, then unsubscribe.

# Learnings: CinemaEngine Camera Capture & Video Export

- **"The camera doesn't work" was literally true — the module had none:** the CinemaEngine's only inputs were a file `<input type="file">` and AI image synthesis; `grep` for `getUserMedia`/`mediaDevices`/`<video>` returned nothing under the module. Before debugging a capture feature, confirm the feature exists — and check the *renderer* too, because the preview painted per-clip gradients and never touched `clip.url`, so uploaded media was invisible as well.
- **`navigator.mediaDevices` vanishes on an insecure origin:** `getUserMedia` is secure-context-only, and browsers *remove the whole namespace* rather than throwing, so an `http://<lan-ip>` dev server or tunnel reads as "no camera". Detect `window.isSecureContext === false` and report a dedicated `NEEDS HTTPS` state instead of a generic unsupported one. Capacitor's `https://localhost` Android scheme satisfies the requirement.
- **Android denies the request before it ever prompts:** the WebView needs `android.permission.CAMERA` declared in `AndroidManifest.xml` (Capacitor's `BridgeWebChromeClient` grants `onPermissionRequest` only for permissions the manifest lists) plus `<uses-feature android:required="false">` so audio-only devices can still install. A missing permission looks identical to "camera broken" in the UI.
- **Never `display: none` a `<video>` that feeds a canvas:** a fully hidden media element can stop decoding frames, so `drawImage` silently yields nothing; keep the sink 1px and painted (`opacity: 0.01; pointer-events: none`) and bind the stream with `srcObject` (never a `blob:` URL).
- **A bound stream can still be black:** if another app holds the camera, Android can hand out an authorised track that never delivers pixels — the UI then shows `LIVE` over a frozen frame. Arm a first-frame watchdog (`videoWidth === 0` after ~2.5s ⇒ "no video frames yet, another app may be using the camera") and clear it from the render loop the moment a frame is actually painted.
- **Release the previous stream before requesting a new one:** `getUserMedia` for a second device while one is open fails with `NotReadableError`, so device switching must `stop()` every track first, and the selection must follow the `deviceId` the *browser reports* in `getSettings()` rather than the one requested.
- **A `MediaRecorder.stop()` flush is a microtask:** `ondataavailable` + `onstop` land after the current task, so a synchronous fake makes "discard the take when the camera stops" pass by accident. Fakes must flush in a `queueMicrotask`, and `jest.useFakeTimers()` must then leave `queueMicrotask` unfaked (`doNotFake: ['queueMicrotask']`).
- **`HTMLMediaElement.play()` is not universally implemented and can reject:** a bare `void video.play().catch(...)` throws `TypeError: Cannot read properties of undefined` where `play()` returns `undefined`. Wrap it in a `playQuietly()` helper that tolerates both a missing promise and a synchronous throw.
- **A stub export is worse than a disabled button:** `startVideoExport(config)` returned `{ recorder: { stop: () => {} }, result: Promise.resolve(new Blob()) }`, so `EXPORT VIDEO` ran a 10-second fake capture and downloaded a 0-byte file marked as a successful master. Implement it for real — `canvas.captureStream(fps)` + `MediaRecorder` with a codec negotiated via `isTypeSupported`, and fold in the engine's master bus (`getMasterStream().stream`) so the export isn't silent — and make `result` reject on recorder error so the UI can say so.
- **A real-time capture window must be visible to the user:** canvas capture is inherently real time, so a hidden 10s constant is a product decision nobody made. Expose the window (5/10/30/60s) and report progress from elapsed time; then a hard-coded `64%` "Render Progress" bar becomes obviously wrong and gets bound to the real export.
- **Only claim `REC` while recording:** the HUD painted a literal `REC ●` whenever any clip was on the playhead. Derive the transport badge from real state (`CAM ● LIVE` / `REC 0:07` / `PLAY ▶` / `STANDBY`) — an always-on recording light trains users to ignore it.
- **Tag clips with their provenance:** `VideoClip.source` (`upload` | `ai` | `camera` | `screen`) is what lets the viewfinder mirror apply to camera footage without flipping the artist's uploaded video or making a screen share unreadable, and it documents where a timeline item came from.
- **`fastSeek()` is the opposite of frame-accurate:** it snaps to the nearest keyframe. Frame-accurate scrubbing means assigning `video.currentTime` exactly, and gating on state: while the transport is **paused** seek on every rendered frame, while **playing** only correct past a drift tolerance (~0.12s) or the decoder is re-seeked every frame and stutters. A sub-millisecond epsilon keeps a repeated render at the same instant from re-seeking.
- **Pass the resolved clip time into the sync, don't recompute it:** the render loop already knows `clipLocalTime`; re-deriving it from `videoEngine.currentTime()` duplicates the trim/offset math and drifts from what was actually painted.
- **Off-screen media never stops on its own:** every ingested video element kept decoding after its clip left the playhead. Track the active urls per frame and `pause()` anything cached that is not among them — on phones this is a battery and thermal bug, not a nit.
- **Acquire before releasing when switching capture sources:** a camera switch must release first (the second `getUserMedia` fails while the device is held), but a *screen* share must not — the display picker is independent, and releasing first means a cancelled picker kills a perfectly good live camera. Cancel and denial share `NotAllowedError`, so keep the held stream and report the cancel in the error line instead of stamping an idle status over a running device.
- **A screen share ends from outside the app:** the browser's "Stop sharing" bar ends the display track, so the `ended` handler has to be source-aware ("Screen share ended") and reset `sourceType`, otherwise the UI keeps advertising a share while the OS has already moved on.
- **Never destructure `getDisplayMedia` off `navigator.mediaDevices`:** calling the detached reference throws `Illegal invocation`; check `navigator.mediaDevices?.getDisplayMedia` for support and call it through the object. It is also an independent capability from `getUserMedia`, so it needs its own support flag rather than reusing the camera's.
- **Guard `pause()` the same way as `play()`:** `playQuietly()` existed because `HTMLMediaElement.play()` is not universally implemented, but `ngOnDestroy` and the scrub sync still called `media.pause()` bare — so every fixture teardown holding a playing element threw on hosts with a partial media implementation. A helper that is only used in some call sites is a bug waiting to be found.
- **`jest.restoreAllMocks()` in a spec `afterEach` runs *before* Angular's fixture teardown:** Angular registers `TestBed.resetTestingModule()` at the root, so the file's own `afterEach` (registered later) unwinds first (LIFO). Prototype-level stubs installed with `jest.spyOn` are therefore gone by the time `ngOnDestroy` runs, and jsdom's "not implemented" reporter logs a stack trace per test. Install durable stubs on the prototype (`Object.defineProperty`) instead of spies when the teardown path needs them.
- **Anything only exercised during `ngOnDestroy` is untested by default:** the pause/`src` reset/URL-revoke/camera-release path had zero specs, which is exactly why the unguarded `pause()` survived. Angular destroys the fixture automatically, so a teardown defect surfaces as console noise rather than a failure — assert the teardown explicitly (pause called, `src` cleared, stream released, object URLs revoked, and that a throwing host cannot break `destroy()`).
- **Playwright's default browser has no camera at all:** the default headless launch is the headless *shell*, which implements no media capture — every `getUserMedia` call there rejects with `NotSupportedError` (`{video: true}` included), while `deviceId: {exact}` rejects with `OverconstrainedError` and makes it look like a constraint bug. A camera spec on that binary measures the harness, not the app; launch the full Chromium (`test.use({ channel: 'chromium' })`, binary `chromium-*` not `chromium_headless_shell-*`) plus `--use-fake-device-for-media-stream` before believing any result.
- **`NotSupportedError` is not "no camera":** it means the host implements no capture at all — in-app WebViews, stripped-down or headless builds. Folding it into the `unavailable` state advertised `NO CAMERA` and sent operators hunting for hardware that was never the problem; it now has its own state, and it must also suppress the retry affordance, because asking again cannot conjure an implementation.
- **Status copy must be source-aware, not just the label:** `REQUESTING ACCESS…` came with the fixed sentence "Waiting for the camera permission prompt" even while a *screen* picker was open. That describes a prompt that is never going to appear, which is indistinguishable from a camera that refuses to start — the status detail, the denied/unavailable/embedded wording and the embedded message all have to branch on whether the in-flight request was `camera` or `screen`.
- **Same-origin iframes inherit the `self` allowlist; cross-origin ones do not:** a frame with no `allow` attribute still gets the camera when it is same-origin, so a same-origin harness "proves" framing is harmless. Only a genuinely cross-origin frame reproduces the failure — and compare against both `document.permissionsPolicy` and the deprecated `document.featurePolicy`, because modern Chromium exposed only the latter here (`undefined` on `permissionsPolicy`) and reading just the new name makes a policy refusal look like a user denial, with advice pointing at the wrong setting.
# Learnings: CinemaEngine Project Persistence

- **The edit died with the tab:** `VideoEngineService` held the entire timeline — tracks, clips, markers, lower thirds, delivery preset — in signals with nothing writing any of it down, so a film or a broadcast rundown could not survive a reload. Long-form work is the whole point of the module; "the module has no persistence" is as load-bearing a finding as "the module has no camera".
- **Do not park non-audio records in the `projects` store:** `ProjectService.loadProjects()` reads that store back whole and treats every record as an audio `Project` (bpm, key, mixer tracks), so a video timeline saved alongside them would surface in the Studio project list as a broken project. Give the CinemaEngine its own store and bump the DB version — the existing `onupgradeneeded` block already documents that pattern, and an upgrade adds a store without touching existing data. Verify the migration by planting the *previous* version's schema on a blank same-origin page before the app ever loads; otherwise the app creates the new version itself and the upgrade path is never exercised.
- **A resolved write is not a completed write:** `LocalStorageService.saveItem` returns early when IndexedDB is missing or its open failed, so the promise resolves whether or not anything was stored. Any caller that reports success needs an explicit availability check first (`isAvailable()`), or the UI announces saves that never happened.
- **Save session-scoped media as absent, not as a dead reference:** ingested files and camera takes are `blob:` object URLs that die with the document, while a `data:` url carries its own bytes. Storing the blob url verbatim produces a clip that looks like it has media and renders nothing; storing it empty lands in the state the renderer already understands as "staged, not shot yet", and the reopen path can then say plainly how many clips need re-ingesting.
- **A snapshot must be deep-copied and a restore must not trust the record:** a snapshot that aliases live arrays is rewritten by the next edit, and a hand-edited or partially-written record can place one clip in two lanes. Copy on the way out, and on the way back derive lane membership from the track the clip is stored on rather than the `trackId` it claims.
- **Bumping an IndexedDB version makes `onblocked` reachable, and an unhandled block hangs forever:** if another tab holds the database open at an older version the upgrade cannot start, and *neither* `onsuccess` nor `onerror` fires — so a `dbReady` latch that only those two resolve never settles, every await on it hangs, and a caller waiting on availability sits on its in-flight flag showing neither success nor failure. Handle `onblocked` (resolve, and record the reason) and register `onversionchange` to `close()`, or your own tab becomes the thing blocking the *next* upgrade. Test it by holding the previous version open in a second tab and reloading — the regression is "the save settles and the controls come back", not any visible message.
- **"I cannot store" and "another tab is holding it" are different problems:** the browser in the second case is perfectly capable of storing data, and only one of the two messages leads the operator to a fix. Carry the *reason* out of the storage layer rather than a boolean, and let it pick the wording.
- **Resolve an overwrite target from storage, not from the in-memory list:** a refresh that fails empties the list while the record is still on disk, so an id looked up in that list comes back undefined and the save mints a fresh id — forking a duplicate and orphaning the original. Read the record back by id, and write under the id the caller supplied.
- **A written-but-never-read format version is a trap:** `snapshot.version` was stamped on every save and ignored on every load, so a record from a different build would have been read as the current shape and silently lose whatever it carried that this build does not know about. Compare it and refuse, because a refusal is a message the operator can act on and a silent partial load is not.
- **Do not report one condition from two places:** a persistent state notice plus a transient error field both set from the same cause printed the identical sentence twice in the panel. Keep the persistent cause in the state-derived notice and let the error field carry only one-off failures. A strict-mode locator violation is how this surfaced — two elements matching where one was expected is a product bug, not a test nit.
- **A cache keyed by url has to follow the timeline, not the session:** `mediaCache` held decoded `<img>`/`<video>` per clip url and was only emptied in `ngOnDestroy`. That was survivable while a timeline could only grow by ingesting files, but "open a project" replaces every lane at once, so each open left the previous project's decoded takes resident — and a decoded video is far larger than the file it came from. Evict on the replace path, and delete the *decoding* without revoking the object url: a project reopened later in the same session must still find its media.
- **Audit for capability nothing reaches:** grepping each public service method against the component found `barsForDuration` (the engine's own idea of how a shot length is expressed, and the unit a music-video cut is actually planned in) and `markerNear` with no caller at all. A helper with no caller is either a missing feature or dead weight — decide which, rather than leaving it to be rediscovered.
- **A round trip has to be tested across two engines:** the service is `providedIn: 'root'`, so restoring into a second `TestBed.inject` hands back the same instance and a `restore` that never ran still looks like it worked. Reset the testing module between the save and the reopen — and re-save order assertions need a controlled clock, because two saves in the same millisecond tie and a stable sort passes them by accident.

- **A dead script reference silently disables an entire test suite:** `playwright.config.ts` started the app with `npm run dev:web`, a script that does not exist, so no e2e run could ever bring up a server. Verify the `webServer.command` in the package manifest before concluding the app is broken — and note `dev` already honours `PORT`, so pinning the port belongs in the config's `env`.

# Learnings: S.M.U.V.E. Persona & Full-Control Authority

- **A persona needs exactly one source of truth:** Settings, the Profile Editor cards, the Persona Lab, the onboarding questionnaire, and both prompt builders each carried their own persona list (`Aggressive Manager` / `Ominous Dominator` / `Encouraging Mentor` vs the four modes the UI rendered), so an onboarding answer landed on a label no other surface recognized and the prompt fell through to a generic assistant. Keep one catalog (`types/persona.types.ts`) with a `normalizePersona()` that resolves *legacy and unknown* ids back to the intended default — never to "no persona".
- **"Default unless the artist changes it" means unknown values are not a third state:** any value that is not one of the canonical ids resolves to the shipped default (Ominous Musical GOD), so a stale profile or a half-written settings object cannot silently strip the character out of the prompt.
- **Persona, profanity, intensity, and command authority are independent axes:** folding them into one another is how the character gets neutered — turning explicit language off must change vocabulary only, and the arrogance/menace/sadistic wit have to survive intact. Assert that in the spec, because it is the exact regression that a "safety polish" pass introduces.
- **A confirmation gate that can never be satisfied is just a broken feature:** the control service refused every `requiresConfirmation` command outright, so `/project save` and `/export` were unreachable even with full control granted. Gate *capability* on the artist's setting (`aiTotalControlEnabled`), then let the granted path execute — irreversible/outward-facing actions ask, faders do not.
- **Navigation must mirror `app.routes.ts`, and normalize spacing:** the destination map covered ~17 of the app's modules and matched on exact keys, so "open the remix arena" failed while `/go remix` worked. One map, keyed by the words an artist types (`remix arena` → `remix-arena`), keeps "S.M.U.V.E. drives the whole app" true.
- **Never write a signal from a getter a template calls — NG0600 blanks the page:** `SecurityService.getSecurityAudit()` (bound directly in `hub.component.html` and inside a `computed` in Settings) called `validateSession()`, which did `isSessionValid.set(...)` during Angular's render pass. The whole Hub landing page crashed. Derive that state with `computed()` instead; a helper that mutates state is a helper that only works outside the template.
